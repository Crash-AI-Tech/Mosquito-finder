# Mosquito Finder 验证与调试基线

本文档用于落地 Phase B，目标是统一工程侧的调试口径，确保后续对坐标、状态机、触发条件和性能的调整都有一致基线。

## 1. 当前必须观察的链路

调试时必须同时观察以下四条链路，而不是只看最终红框是否出现：

* 相机帧尺寸与屏幕预览尺寸是否一致映射。
* Stage 1 候选数量是否稳定。
* Tracker 是否能够在轻微手抖下保持目标。
* Stage 2 触发条件是否与用户直觉一致。

## 2. 必看指标

首轮必须稳定暴露以下指标：

* Stage 1 耗时。
* Stage 2 耗时。
* 候选数。
* 稳定追踪目标数。
* 当前变焦倍数。
* 中心目标距离。
* 当前触发条件。

## 3. 坐标校准检查项

每次修改相机预览、变焦、裁切、Overlay 映射后，都要逐项确认：

* 屏幕中心准星是否对应真实触发中心。
* 目标框在 1x、3x、5x 下是否仍然贴合目标。
* 预览层 `AspectFill` 裁切后，Overlay 是否仍按相同偏移量映射。
* Stage 2 ROI 是否基于真实像素区域，而不是屏幕坐标误差区域。

## 4. 状态机检查项

状态流转必须符合以下路径：

* `idle -> scanning`
* `scanning -> engaging`
* `engaging -> killing`
* `engaging -> scanning`
* `killing -> scanning`

重点检查：

* Stage 2 已经启动但界面仍处于 `scanning` 的错误状态。
* 目标已经消失但 `engaging` 没有复位。
* Stage 2 已给出否定结果但 UI 仍保留活动目标。

## 5. 性能检查项

首轮调优先关注稳定性，而不是极限精度。

最低要求：

* 搜索阶段保持可用帧率。
* 串行帧处理不出现明显状态错乱。
* Stage 2 不连续抖动触发。
* 目标丢失时能够稳定复位。

## 6. 建议测试场景

每轮代码变更至少覆盖以下场景：

* 干净白墙，无目标。
* 有污渍白墙，无目标。
* 墙上存在真实蚊子。
* 轻微手抖扫视。
* 靠近目标并切换 3x/5x。
* 强补光和弱补光各一次。

## 7. 本轮已落地的工程基线

当前代码已经补齐以下底座能力：

* 相机帧处理回到串行链路，避免并发帧导致状态和追踪错位。
* 预览尺寸会同步到触发器，用于统一中心区与屏幕映射。
* Stage 2 活动目标与状态机已接通，减少“分类已开始但 UI 状态未更新”的脱节。
* UI 已暴露基础诊断面板，便于后续现场调试与录屏分析。

## 8. 后续建议

在进入真实模型训练前，先用当前诊断面板把以下问题跑通：

1. 候选是否稳定进入中心区域。
2. 触发器是否只在合理时机触发。
3. 状态机是否在误报和目标丢失时稳定复位。
4. 画面缩放和 Overlay 是否在多机型下仍然一致。
