# Mosquito Finder (猎蚊者) 产品需求文档 (PRD)

## 1. 产品概述 (Product Overview)

**产品名称**: Mosquito Finder (猎蚊者)
**核心理念**: 利用手机摄像头和计算机视觉技术，辅助用户在复杂背景（如白墙、暗处）下快速定位并确认蚊子，解决“看得到听得到但找不着”的痛点。
**核心机制**: **两阶段检测法 (Two-Stage Detection)** —— 先“广撒网”发现可疑点，再“狙击”确认目标。

---

## 2. 核心功能流程 (Core Workflow: The Hunting Flow)

产品体验模仿“夜视仪”或“狩猎”体验，强调直觉引导与确认快感。

### 阶段一：广角搜索 (Radar Mode / Scan)

*   **场景**: 用户手持手机扫视墙面、天花板。
*   **视觉风格**: 
    *   绿光/微光夜视仪风格。
    *   自动开启手电筒 (Flashlight ON)。
*   **交互**:
    *   屏幕不显示确定的红框。
    *   使用**半透明黄色光圈**或**动态波纹**标记所有“可疑点”（包含蚊子、污渍、钉子眼）。
    *   引导用户直觉：“这里可能有东西”。
*   **技术策略 (MediaPipe)**:
    *   **调用镜头**: 主摄 (1x Wide)。
    *   **核心算法**: 使用 **MediaPipe** 进行轻量级图像处理与特征点检测。
        *   *初期策略*: 利用 MediaPipe 的 Image Processing 能力或轻量级 Object Detection 模型，调低置信度阈值，追求**高召回率 (High Recall)**。宁可错杀（标记污渍），不可放过。

### 阶段二：狙击确认 (Sniper Mode / Engage & Kill)

*   **场景**: 用户发现黄色光圈后，本能地将手机靠近目标，或手动变焦。
*   **触发机制** (满足任一):
    *   屏幕中心对准黄色光圈。
    *   用户手动切换至 3x/5x 变焦。
    *   加速度计检测到明显的“靠近”动作。
*   **交互**:
    *   **锁定**: 当疑似目标占据画面比例变大（如 >50x50px）。
    *   **确认 (Kill)**: 
        *   若是蚊子：光圈**瞬间变红**，伴随手机**震动反馈**。显示置信度 (e.g., "Mosquito 98%")。
        *   UI 展示画中画 (PiP) 特写，辅助用户看清细节。
        *   若非蚊子：光圈消失或变为灰色叉号。
*   **技术策略**:
    *   **调用镜头**: 自动切换长焦或数字裁切放大。
    *   **核心算法**: 高精度推理 (可兼容 YOLOv11)。
        *   针对屏幕中心 ROI (Region of Interest) 进行精细化纹理、形状识别。

## 3. 技术架构与实现 (Technical Implementation)

### 3.1 核心视觉栈 (Vision Stack)

*   **初期阶段 (当前)**: **MediaPipe**
    *   作为主要的视觉处理管道。
    *   利用 MediaPipe 跨平台优势，快速构建检测链路。
    *   用于 Stage 1 的快速斑点/物体初筛。
*   **后期扩展**: **YOLOv11**
    *   集成轻量化 YOLOv11 模型处理 Stage 2 的精确认别。
    *   通过 MediaPipe 的 Custom TFLite Model Inference 接口或独立 TFLite 解释器运行。

### 3.2 关键挑战解决方案

*   **对焦呼吸效应 (Focus Breathing)**
    *   *问题*: 靠近过程中自动对焦导致画面忽大忽小，目标丢失。
    *   *解法*: iOS `AVCaptureDevice` 锁定对焦模式，或 UI 增加**中心十字准星**，强制对焦于屏幕中心。
*   **目标追踪 (Tracking)**
    *   *问题*: 手抖导致目标在屏幕上乱晃。
    *   *解法*: 引入 **KCF** 或 **DeepSort** 追踪算法（或利用 MediaPipe Objectron/Tracking 功能）。一旦 Stage 1 锁定黄点，算法强行“咬住”该像素区域，即使画面抖动，标记框也需紧贴目标。
*   **动态范围 (HDR)**
    *   *问题*: 强光反光或阴影导致目标不可见。
    *   *解法*: 强制开启 HDR 视频流；强制常亮闪光灯补光。

## 4. UI/UX 详细设计

1.  **启动页**: 快速进入“狩猎模式”，无繁琐设置。
2.  **HUD (平视显示器)**:
    *   极简风格，避免遮挡视野。
    *   准星：屏幕中心常驻十字准星。
    *   目标标记：
        *   **可疑**: 黄色呼吸光圈/波纹。
        *   **确认**: 红色实线框 + 红色文字标签 + 震动。
3.  **反馈机制**:
    *   视觉：颜色变化 (黄 -> 红/灰)。
    *   触觉：发现可疑点轻微震动，确认目标强烈震动。

## 5. 开发路线图 (Roadmap)

1.  **Phase 1 (MVP)**
    *   集成 MediaPipe 环境。
    *   实现 Stage 1 广角检测：识别墙面小黑点/斑点，渲染黄色光圈。
    *   实现基础手电筒与变焦控制。
2.  **Phase 2 (Optimization)**
    *   引入追踪算法，解决手抖丢标问题。
    *   优化对焦逻辑，防止呼吸效应。
3.  **Phase 3 (Precision)**
    *   集成 YOLOv11 (或训练专用 Mosquito 模型) 到 Stage 2。
    *   实现画中画特写与震动反馈。

## 6. 基于当前代码实现的现状判断 (Code Reality Check)

以下判断基于当前工程代码，而不是仅基于上方的理想方案描述。

### 6.1 当前已经具备的能力

*   已有完整的 iOS 相机原型链路：相机预览、变焦、对焦锁定、手电筒、运动检测、震动反馈。
*   已有 Stage 1 原型：能够在视频帧中做“暗点/可疑点”级别的启发式扫描，并在界面上绘制目标标记。
*   已有基础追踪链路：使用 Vision 追踪目标，并通过状态机驱动可疑、确认中、已确认、已排除等状态。
*   已有主界面和夜视风格 HUD，适合继续迭代为正式产品界面。

### 6.2 当前距离“真实发现蚊子”还缺什么

*   **Stage 1 仍然是启发式暗点检测，不是蚊子检测**。
    *   现有逻辑更像“找墙上的小黑点”，对污渍、钉子孔、阴影、墙面纹理会产生较高误报。
*   **Stage 2 还没有真实模型**。
    *   当前分类器没有接入真实的 CoreML/TFLite 蚊子模型，主要是启发式模拟判断，不能作为真实识别依据。
*   **文档中的 MediaPipe / YOLO / OpenCV 方案尚未实际落地到工程依赖和模型资源中**。
    *   当前工程里还没有对应模型文件与完整推理接线。
*   **坐标系、触发条件和状态流转还需要统一校准**。
    *   当前追踪框、屏幕中心触发区域、Stage 2 ROI 和 UI 映射需要按真实预览变换统一，不然容易出现“看起来对准了，但算法没有正确锁定”的问题。
*   **现有 UI 是功能性原型，不是高级产品界面**。
    *   已有夜视和 HUD 氛围，但视觉层级、品牌感、动画节奏、信息架构还不足以支撑“高级、可信、专业”的体验。

### 6.3 结论

当前项目已经有一个可继续迭代的技术原型，但它更接近“猎蚊视觉演示 Demo”，还不是“可以真实发现蚊子”的产品。后续工作重点不应直接停留在换皮或简单接一个模型，而是要先建立**数据闭环 + 真实模型 + 稳定视觉管线 + 高级界面**四条主线。

## 7. 面向真实检测的更新目标 (Updated Product Goal)

本节作为后续改造的执行基线，待确认后实施。

### 7.1 第一阶段真实目标定义

第一阶段不追求“任何场景都能抓到飞行中的蚊子”，而是聚焦一个更可落地、可验证、可迭代的目标：

*   **目标对象**: 停落在墙面、天花板、窗帘等静态表面的蚊子。
*   **使用场景**: 室内、低光环境、用户手持手机搜索。
*   **设备策略**: 后置主摄 + 手电筒常亮 + 受控变焦。
*   **交互策略**: Stage 1 高召回地找出候选目标，Stage 2 在中心 ROI 内做真实确认。

### 7.2 第一阶段非目标

以下能力不作为第一阶段承诺目标：

*   飞行中的高速蚊子实时检测。
*   户外复杂背景下的通用小虫识别。
*   对所有墙纸纹理、花纹织物、强反光表面的稳定识别。
*   在没有补光、没有对焦控制、没有变焦协助的条件下保证高准确率。

### 7.3 目标验收指标 (Target Metrics)

以下指标为计划目标值，后续根据数据集和实测结果调整：

*   Stage 1 候选召回率：对“肉眼可见的停落蚊子”达到 **>= 90%** 的候选命中率。
*   Stage 2 最终确认精度：达到 **>= 85% Precision**。
*   空白墙面误报：控制在 **< 1 次/分钟**。
*   用户从发现可疑点到得到确认结果的平均耗时：**< 1.5 秒**。
*   主搜索体验帧率：维持在 **20-30 fps** 的可用区间。

## 8. 更新计划 (待确认后执行)

### Phase A: 问题收敛与数据闭环

目标：先把“什么叫发现蚊子”定义清楚，并建立训练与评估依据。

*   明确首版任务边界：只做室内停落蚊子，不把范围扩到飞行目标。
*   建立数据采集规范：距离、光照、墙面材质、设备型号、变焦倍数、是否开闪光灯。
*   建立标注规范：目标框、蚊子朝向、是否遮挡、背景类别、难例标签。
*   采集第一批真实数据：
    *   正样本：蚊子图像/视频帧。
    *   负样本：污渍、裂缝、钉眼、蚂蚁、飞蛾、阴影、织物纹理等高相似物。
*   建立离线评估集与基准脚本，用同一套指标评估 Stage 1 和 Stage 2。

### Phase B: 视觉管线校准与工程基础修正

目标：把当前原型改造成可以稳定承载真实模型的工程底座。

*   统一坐标系统：打通相机像素坐标、预览层坐标、Overlay 坐标、Stage 2 ROI 坐标。
*   修正阶段流转：让可疑目标发现、锁定、确认、排除在状态机中形成闭环，而不是分散在多个对象内的局部更新。
*   增加性能与调试观测：帧耗时、误触发次数、候选数量、Stage 2 命中率、设备温度与掉帧情况。
*   优化相机策略：曝光/对焦/手电筒/变焦的切换规则前置设计，避免靠近目标时出现对焦呼吸和曝光漂移。
*   将当前处理流程收敛到可控的串行视觉队列，避免主线程 UI 和视觉处理互相干扰。

### Phase C: Stage 1 升级为真实候选生成器

目标：从“找黑点”升级为“以高召回率找出疑似蚊子候选”。

*   保留轻量化思路，但替换当前单一暗点启发式为**多特征候选生成**：
    *   平滑背景检测。
    *   多尺度小目标增强（如黑帽/DoG/Laplacian 类思路）。
    *   局部对比度与边缘密度筛选。
    *   长宽比、面积、细长度等形态学过滤。
    *   3-5 帧时间一致性过滤，压制瞬时噪点。
*   把 Stage 1 输出从“一个框”提升为“候选 + 分数 + 触发原因”，方便后续调参与 UI 呈现。
*   优化追踪器，让目标在轻微手抖、微小位移、短暂丢帧下仍能稳定保持。

### Phase D: Stage 2 接入真实蚊子识别模型

目标：让“确认是蚊子”基于真实数据训练结果，而不是启发式模拟。

建议按两步走：

*   **D1. 先做 ROI 二分类器**
    *   输入为 Stage 1 / Tracker 裁出的高质量 ROI。
    *   使用轻量模型导出 CoreML，在设备端完成推理。
    *   先验证“在可疑目标已经被放大和居中后，是否能可靠分辨蚊子与非蚊子”。
*   **D2. 再评估是否需要小目标检测器**
    *   如果二分类器对复杂背景或姿态变化仍不够稳，再接入 YOLOv11-Nano 级别的小目标检测模型，或自训练的小目标检测器。
    *   检测器只对中心 ROI 或短时抓拍序列运行，避免全屏重模型常驻。

补充要求：

*   使用真实负样本做 hard negative mining，重点压制墙面污渍、孔洞、裂纹、其他小虫。
*   通过离线 PR 曲线和在线实测共同确定阈值，而不是只凭主观观感调阈值。
*   支持设备侧分档策略：不同机型可以配置不同输入尺寸、推理频率、变焦策略。

### Phase E: 高级界面改造 (Premium UI Refresh)

目标：界面不只是“夜视滤镜”，而是一个可信、克制、专业的猎蚊仪表系统。

设计方向：

*   视觉语言从“纯绿色滤镜”升级为“战术光学仪表”风格。
*   保持低遮挡，但增强高级感、可读性、专业感。

具体改造方向：

*   **视觉体系**:
    *   采用更克制的深色基底，而不是整屏单一绿色蒙层。
    *   用分层色彩表达状态：可疑为琥珀黄，锁定为高亮橙，确认为警示红，系统信息为冷绿/磷光绿。
*   **排版体系**:
    *   主信息与辅助信息采用有层次的字体组合，避免当前界面过于默认化。
    *   数值、计时、倍率、锁定状态采用仪表风格字形与对齐方式。
*   **HUD 重构**:
    *   中央准星升级为具备“稳定区”和“确认区”的双层瞄准结构。
    *   顶部增加环境/状态信息，如搜索质量、补光状态、对焦状态、倍率档位。
    *   底部控制栏重构为更专业的一体化控制面板，而非简单按钮横排。
*   **确认体验**:
    *   增加 PiP 特写卡片，用于展示 Stage 2 正在确认的局部图像。
    *   确认成功时采用克制但有力量的动画、闪烁和触觉组合，而不是单一弹层。
*   **动效原则**:
    *   动效要服务于状态变化和目标稳定感，不做多余装饰。
    *   强调“锁定感”“吸附感”“确认感”，弱化廉价扫描特效。

### Phase F: 实地验证与闭环迭代

目标：用真实家庭场景把系统调到可用，而不是只在理想测试图上有效。

*   建立真实场景测试集：白墙、灰墙、脏墙、木门、窗帘、阴影角落、反光区域。
*   每一轮测试都记录：是否发现、误报原因、确认时间、最终截图/视频。
*   将误报样本持续回流到数据集中，形成 hard negative 闭环。
*   做设备分层调优，避免单一机型效果好、换一台机器就失效。

## 9. 推荐执行顺序 (Implementation Order)

为了避免“先做 UI 漂亮了，但识别仍不可信”，建议按下面顺序推进：

1. 先完成 **Phase A + Phase B**，明确任务边界、修正坐标与状态闭环、补齐调试能力。
2. 再完成 **Phase C**，把 Stage 1 升级到可承载真实产品的候选生成能力。
3. 然后完成 **Phase D**，接入真实模型并建立离线/在线指标体系。
4. 在检测闭环基本可信后，推进 **Phase E** 做高级界面重构。
5. 最后用 **Phase F** 做实地验证和 hard negative 闭环迭代。

这个顺序的核心原则是：**先把“能不能真实发现蚊子”做实，再把“看起来像不像高级产品”做满。**
