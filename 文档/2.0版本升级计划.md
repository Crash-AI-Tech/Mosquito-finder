# Mosquito Finder 2.0 版本升级计划

更新时间：2026-06-27

## 1. 目标

2.0 版本围绕两个方向升级：

1. **界面和交互**：从“战术 HUD 工具”升级为“引导式猎蚊体验”。用户打开 App 后，不需要理解模型和参数，只需要跟随扫描、靠近、放大、确认的提示完成一次有效搜索。
2. **模型识别准确率**：从当前“全帧检测分数直接确认”升级为真正的两阶段视觉管线：Stage 1 大范围高召回搜索可疑区域，Stage 2 在用户靠近/放大后对局部高清 ROI 做高精度确认。

核心产品指标：

- 首次使用用户能在 15 秒内理解如何开始扫描。
- 大范围扫描时能稳定标出“可能有蚊子”的方向和区域，而不是只给零散框。
- 用户靠近候选区域后，App 能给出清晰的“继续靠近 / 放大 / 对准 / 已确认”反馈。
- 真实家庭场景下误报明显下降，且漏掉远处小目标的概率下降。

## 2. 当前代码现状

### 2.1 交互和界面

当前主界面集中在 `HuntingView`、`TargetOverlayView`、`RadarPulseView`、`TargetEffectsScene`：

- 已有深色相机全屏、绿色扫描线、准星、黄色/红色目标框、冻结帧和底部确认面板。
- 已有首次任务引导 `MissionGuideOverlay`，但引导和实时识别状态没有形成强闭环。
- 启动页视觉有“雷达 / 夜视仪”风格，但仍偏功能说明，缺少高级产品的层次、节奏和情绪设计。
- 设置页 `SettingsView` 已支持 D-FINE、YOLOX、Classic 三种模型和两阶段参数，但整体更像工程调参面板，不适合普通用户。
- Trophy 页面有统计数据，但还没有形成复用价值：用户看不出“这次为什么成功 / 下次怎么更快找到”。

### 2.2 模型管线

当前视觉入口在 `TargetCoordinator.processFrame()`：

- Stage 1：
  - Classic 模式：暗点扫描 + 局部对比度 + 背景平整度。
  - Detector 模式：D-FINE / YOLOX 全帧 416 输入检测，低阈值产生候选框。
- Tracker：
  - 当前 `ObjectTracker` 追踪稳定目标，`stableFrameCount` 控制稳定帧数。
- Stage 2：
  - Classic 模式：对 ROI 调用 `MosquitoClassifier.mlmodel`。
  - Detector 模式：目前不是高清 ROI 复检，而是直接用 Stage 1 detector 的 tracking confidence 通过高阈值确认。

这意味着当前 D-FINE / YOLOX 模式虽然在产品文案上是两阶段，但技术上更接近“全帧检测 + 稳定分数门控”。2.0 需要把它改成真正的：

```text
Stage 1: wide search / high recall / low confidence threshold
Stage 1.5: tracking + visual guidance + user movement/zoom coaching
Stage 2: high-resolution local confirmation / high precision
```

### 2.3 训练和数据现状

已有数据和结论：

- Kaggle low-light mosquito：约 7,487 个有效 bbox 样本，是当前最可用的真实检测数据。
- Hugging Face mosquito species detection：已有 bbox，但混入 YOLOX 后验证集表现下降，需要先做分布和标注质量分析。
- Mosquito Alert Tigapics：约 40,842 张可用图，但只有图像级物种标签，没有 bbox。不能直接当检测框训练集。
- 当前 YOLOX 最佳 F1：约 73.65%，高精度点接近 94.95% precision 但 recall 只有 12.62%。
- Mosquito Alert 伪标注等权混入曾造成退化，说明伪标签必须人工审核、分层采样、低权重使用。

## 3. 外部调研结论

### 3.1 小目标检测方向

蚊子在手机画面里通常是极小目标，远距离时可能只有十几个像素。小目标检测的主要难点是分辨率不足、背景纹理干扰、类别不平衡、标注噪声和真实场景域偏移。

可采用的方向：

- **切片/局部高分辨率检测**：SAHI 通过把高分辨率图像切成重叠 patch 来提升小目标检测效果。论文报告在多个检测器上能显著提升小目标 AP，适合我们做 Stage 2 高清局部确认。
- **多尺度特征和高输入分辨率**：Stage 1 不宜只把全帧压到 416；可保留低分辨率全帧搜索，同时对可疑区域做 640/768/1024 局部复检。
- **低分检测框也要追踪**：ByteTrack 的思想是不要过早丢弃低分框，而是通过时序关联判断是否是真目标。适合大范围搜索阶段提高召回。
- **硬负样本挖掘**：家庭墙面上的污点、螺丝、阴影、纹理、灰尘是主要误报来源。模型提升必须依赖真实手机失败样本，而不是继续堆公开数据。

### 3.2 模型候选

现有模型：

- D-FINE：定位精度强，适合主 detector，但当前本地训练和 CoreML 导出链路需要继续稳定。
- YOLOX：已有训练、导出和评估链路，适合作为可控 baseline。
- Classic CNN：作为 Stage 2 ROI fallback 价值仍高，尤其适合“放大后确认”。

建议新增评估：

- RF-DETR nano：2025 之后的轻量 DETR 路线，论文声称在实时 detector 上有更好的精度/延迟 Pareto，可作为 2.0 研究分支，不直接替换线上。
- MobileNetV3 / MobileViT 分类器：适合做 Stage 2 ROI 分类器，尤其是对高清裁剪图做蚊子 / 非蚊子二分类。
- SAHI 风格切片推理：不一定直接引入 Python SAHI 到 App，而是在 iOS 内实现轻量的“候选区域扩展 + 高分辨率裁剪 + 局部模型确认”。

### 3.3 iOS 端实现原则

- Core ML 仍应使用 `MLModelConfiguration.computeUnits = .all`，优先让系统调度 CPU/GPU/ANE。
- 避免每帧跑重模型；应使用帧率节流、运动稳定判断、候选追踪和局部触发。
- Camera、torch、focus、zoom 不只是功能按钮，而应成为引导闭环的一部分：环境太暗、画面抖动、候选太小、未对准时都给用户明确指令。

## 4. 2.0 产品设计方案

### 4.1 设计方向

视觉关键词：

- 深黑相机底、低饱和科技绿、冷白文字、少量红色警报。
- 少用“游戏化按钮堆叠”，多用专业仪器式反馈。
- 当前绿色战术 HUD 可以保留，但要降低噪声，让用户注意力集中在候选目标和下一步动作。

交互关键词：

- **引导式搜索**：告诉用户现在应该“慢扫墙面”“停稳”“靠近黄色区域”“放大到 2x”“保持中心”。
- **渐进确认**：不要突然红框；先显示候选强度、稳定度、距离中心、放大要求，再进入确认。
- **失败可解释**：没找到时告诉用户可能原因：太暗、太晃、背景太乱、离得太远。

### 4.2 主流程重构

#### Step A：启动前准备

替换当前静态功能说明为“30 秒猎蚊任务卡”：

- 第 1 步：打开手电，扫浅色墙面。
- 第 2 步：看到黄色提示，慢慢靠近。
- 第 3 步：目标进中心后放大确认。

实现：

- `MissionGuideOverlay` 改为可复用的 `GuidedMissionSheet`。
- 支持“今天不再显示”，但设置页可重新打开。
- 引导不使用长文字，改用 3 张短动效卡片。

#### Step B：搜索模式

当前 UI 是“扫描中 + 多个黄色框”。2.0 改成：

- 大范围候选用“方向引导”和“热区提示”，不要一开始就画太多框。
- 候选按稳定度聚合成 1-3 个优先目标。
- 顶部状态显示当前环境质量：
  - 光线：OK / 太暗
  - 稳定：OK / 太晃
  - 背景：OK / 纹理复杂
  - 目标：未发现 / 有候选

新增状态：

```swift
enum GuidanceState {
    case scanning
    case holdStill
    case moveCloser
    case centerCandidate
    case zoomIn(required: CGFloat)
    case confirming
    case confirmed
    case noSignal(reason: NoSignalReason)
}
```

#### Step C：候选引导

当 Stage 1 发现候选：

- 屏幕边缘显示方向箭头，提示用户移动相机。
- 候选进入中心区域后，显示“保持中心 / 放大到 2x”。
- 如果目标太小，不直接判定失败，而是提示靠近。
- 如果目标稳定超过 N 帧，再触发 Stage 2。

#### Step D：确认模式

Stage 2 不再只是高阈值分数门控：

- 用户靠近后，取候选周围扩大 ROI。
- 从当前高分辨率相机帧裁剪局部区域。
- 对 ROI 运行更高输入尺寸或分类器。
- 若仍不确定，提示“再靠近一点 / 再对准 1 秒”，而不是直接清除。

#### Step E：成功和复盘

确认后：

- 保留冻结帧红框。
- 增加“保存为训练样本 / 不是蚊子”两个小操作，但默认隐藏在二级菜单，避免打扰普通用户。
- Trophy 页面增加本次复盘：
  - 找到用时
  - 模型置信度
  - 用户是否靠近/放大
  - 是否生成可训练样本

### 4.3 设置页重构

普通用户设置页只保留：

- 检测模式：智能推荐 / 更敏感 / 更严格。
- 手电筒：自动 / 手动。
- 触觉反馈。
- 语言。
- 重新查看使用指南。

高级设置折叠到 Developer Lab：

- D-FINE / YOLOX / Classic 模型选择。
- Stage 1 / Stage 2 参数。
- 阈值、NMS、稳定帧、冷却时间。
- 诊断信息导出。

这样既保留工程能力，又不会让普通用户被模型概念劝退。

### 4.4 三套突破性视觉 / 交互 / 动效方案

本节基于 2024-2026 年 Apple Design Awards、Apple Human Interface Guidelines、Material 3 Expressive、Google Play 优秀应用趋势，以及当前 App 的“相机扫描 + 两阶段识别”核心场景整理。三套方案都保留 `Stage 1 大范围搜索 -> 用户移动镜头 -> Stage 2 高清确认` 的业务逻辑，但视觉气质、交互节奏和动效语言不同。

#### 参考趋势摘要

Apple 近两年优秀应用给我们的启发：

- Apple Design Awards 2026 中，`Moonlitt`、`Tide Guide` 强调简单优雅的数据表达、跨平台一致性、Liquid Glass 集成、自定义动画和场景化色彩；`(Not Boring) Camera` 强调大按钮、触觉滚轮、复古相机质感和强操作反馈；`Primary` 强调内容优先、UI 退后。
- Apple Design Awards 2025 中，`CapWords` 把拍照行为变成有趣的学习反馈，`Denim` 通过 SwiftUI、滚动转场、mesh gradient、depth effects 和 haptics 增强愉悦感；`Speechify` 的价值在于降低认知负担；`Taobao` 的空间交互强调 3D 对象的摆放、大小、控制和比较。
- Apple Design Awards 2024 中，`Crouton`、`Gentler Streak`、`Rooms`、`Procreate Dreams` 的共同点是：一个清晰主任务、少量高质量控件、强状态表达、动效服务于理解而不是装饰。

Android / Material 近两年优秀设计给我们的启发：

- Material 3 Expressive 强调通过颜色、形状、尺寸和 motion 提升可用性与情绪表达。Google 公开材料和行业报道都指向同一趋势：更大的可触控目标、更有表现力的状态容器、更自然的过渡、更明确的进度反馈。
- Android 16 / Pixel 系统设计趋势强调动态颜色、模糊、实时状态、浮动工具条、进度组件和更强的个性化表达。对我们来说，这适合把“疑似目标 -> 靠近 -> 确认”做成可感知进度，而不是静态阈值提示。
- Google Contacts / Phone 的 Material 3 Expressive 改版方向显示：关键动作按钮更大、更清楚，信息被放进彩色容器，底部导航减少，手势降低误触。对相机猎蚊场景尤其重要，因为用户手持手机移动时不适合操作复杂控件。

结论：

- 2.0 不能继续只是“黑底 + 绿色扫描线 + 工程参数”。
- 成功体验应该像优秀相机 App：用户一眼知道现在该做什么，手指操作少，状态反馈明确。
- 动效要从“扫描装饰”变成“状态转移语言”：发现、靠近、对准、确认、失败都要有不同的节奏和物理感。

#### 方案 A：Liquid Glass Precision / 玻璃精密仪器

定位：最适合 iOS 的高级方案。整体像一台安静、昂贵、可信的生物检测仪，优先体现专业、冷静、准确。

参考来源：

- Apple 2026 `Moonlitt`：优雅、低噪声、跨平台、Liquid Glass。
- Apple 2026 `Tide Guide`：全屏数据图、场景化色彩、自定义动画。
- Apple 2026 `Primary`：UI 退后，把注意力交给核心内容。
- Apple HIG：颜色、动效、实时状态要服务于理解和可访问性。

配色方案：

```text
Base:        #05070A  deep graphite black
Glass:       rgba(255,255,255,0.10) + blur
Primary:     #DCE7F2  cold white
Signal:      #43D7B5  bio cyan
Candidate:   #F2C94C  amber
Confirm:     #FF4D4D  calibrated red
Secondary:   #7D8A99  muted blue gray
```

视觉设计：

- 相机画面保持全屏，所有 UI 都像悬浮在玻璃层上。
- 顶部状态从 “Scanning / Targeting” 改为一条极简检测带：
  - 左：环境质量圆点，光线 / 稳定 / 背景。
  - 中：当前动作，例如“缓慢扫描墙面”。
  - 右：模型状态，Stage 1 / Stage 2。
- 目标框不再是普通矩形，而是“玻璃光学准星”：
  - Stage 1 候选：半透明琥珀柔光环。
  - Centering：目标与中心环之间出现细线牵引。
  - Stage 2：中心环收束成细红框。
- 底部控制区只保留 3 个核心控件：
  - 手电。
  - 变焦滑条。
  - 结束。
  其他调参进入设置页。

交互设计：

- 用户主任务是“跟随提示移动镜头”，不是主动点击。
- 当候选在边缘时，屏幕边缘显示玻璃箭头；箭头大小与距离成正比。
- 目标进入中心后，变焦条自动高亮，提示用户到 1.5x / 2x。
- 如果画面抖动，UI 不报警，只把玻璃层轻微模糊并显示“停稳 1 秒”。
- 确认失败时不直接灰掉，而是显示“不确定，请再靠近一点”，给用户继续完成任务的机会。

动效设计：

- 扫描：慢速呼吸光，不使用高频扫线。
- 发现候选：候选区域像被光学仪器“对焦”一样清晰浮现，时长 220ms。
- 对准：中心环轻微磁吸到目标方向，但不真的移动相机预览。
- 确认：玻璃环快速收束，红色只在最后 120ms 出现，避免误导。
- 失败：候选环淡出并碎成低透明噪点，提示这是噪声而不是错误。

优点：

- 最符合 iOS 高级感。
- 不夸张，适合工具属性和 App Store 审核观感。
- 对“准确、可信”的品牌心智帮助最大。

风险：

- 情绪刺激弱，可能不够“愿意玩”。
- 对动效和玻璃材质细节要求高，否则容易变成普通毛玻璃面板。

适合用户：

- 想要一个严肃、专业、可信的灭蚊辅助工具。
- 对误报很敏感，希望 App 不要显得像游戏。

实现建议：

- SwiftUI 用 `.ultraThinMaterial` / `.regularMaterial` 做面板，但减少大面积玻璃卡片。
- 统一建立 `VisionGlassTheme`，集中管理颜色、blur、stroke、shadow。
- 新增 `GuidanceOrbView`、`GlassTargetReticleView`、`OpticalDirectionCueView`。
- 动效使用 `matchedGeometryEffect`、`PhaseAnimator` 或轻量 `TimelineView`。

#### 方案 B：Material Expressive Hunt / 表现力猎蚊伙伴

定位：最能提升用户意愿的方案。整体更活泼、更易懂、更像一个会引导你的智能伙伴，但仍保持克制，不变成儿童游戏。

参考来源：

- Material 3 Expressive：用颜色、形状、尺寸和 motion 增强可用性。
- Google Phone / Contacts 新趋势：更大的 pill buttons、更少底部导航、更明确的彩色容器。
- Apple 2025 `CapWords`：把拍照行为变成有趣反馈。
- Apple 2025 `Denim`：滚动转场、mesh gradient、depth effects、haptics 带来的愉悦感。

配色方案：

```text
Base:        #101114  soft black
Surface:     #1A1D22  raised surface
Primary:     #8EF0C6  mint
Candidate:   #FFD166  warm yellow
Guide:       #7AB7FF  friendly blue
Confirm:     #FF5A5F  coral red
Accent:      #B58CFF  violet
Text:        #F7F7F2  warm white
```

视觉设计：

- 相机画面上方叠加一个“任务胶囊”，显示当前阶段：
  - 搜索中。
  - 有候选。
  - 请移动。
  - 请放大。
  - 正在确认。
  - 已确认。
- 候选不一开始显示 bbox，而是显示 1-3 个“热区泡泡”。
- 每个热区有生命力：
  - 稳定度越高，泡泡越实。
  - 误报倾向越高，泡泡越松散。
  - 目标靠近中心，泡泡变成准星。
- 底部控件改成 Material 风格大号 pill：
  - Auto light。
  - Zoom。
  - Capture sample / Report wrong result。
- 设置页可继续使用卡片，但每张卡片要有明确图标、色条和一句人话解释，不出现工程术语作为一级文案。

交互设计：

- 新增“任务进度条”，不是时间进度，而是动作进度：
  - Search 25%
  - Center 50%
  - Zoom 75%
  - Confirm 100%
- 用户移动镜头时，方向箭头不是命令式，而是像导航一样提示“往左上慢慢移动”。
- 用户完成一步后，给轻触觉反馈和短促成功动效。
- 如果连续 10 秒没有候选，App 主动建议：
  - “试试浅色墙面”
  - “打开手电”
  - “离墙面近一点”
- 误报/漏报反馈入口更友好：
  - “不是蚊子”
  - “我看到了但没识别”
  这两个按钮只在冻结帧或复盘中出现。

动效设计：

- 扫描：热区泡泡从远处淡入，轻微弹性。
- 方向引导：箭头采用弹性 ease-out，避免机械。
- 进度变化：胶囊横向 morph，颜色从蓝 -> 黄 -> 红。
- 确认：目标泡泡快速压缩成红色印章，触觉 `success`。
- 没找到：胶囊缓慢下沉，进入建议状态，不制造失败感。

优点：

- 用户最容易理解，愿意继续试。
- 对新手友好，适合 App Store 首批用户。
- 交互和模型闭环结合最好，方便收集真实反馈数据。

风险：

- 如果颜色和弹性控制不好，会显得不够专业。
- 需要严格限制装饰元素数量，否则相机画面会被 UI 干扰。

适合用户：

- 普通家庭用户。
- 第一次使用机器视觉工具的人。
- 需要被明确引导“下一步做什么”的用户。

实现建议：

- 建立 `GuidedHuntState` 到 UI component 的映射表，避免散落判断。
- 使用 `ShapeStyle` 和 `contentTransition(.numericText())` 做实时数值变化。
- 热区泡泡用 `Canvas` 或少量 SwiftUI shape 即可，不要引入重型渲染。
- 触觉反馈按状态分层：候选弱震、对准中震、确认强震。

#### 方案 C：Cinematic Macro Lab / 电影微距实验室

定位：最有差异化和记忆点的方案。把 App 从“检测工具”升级成“手机微距狩猎体验”，强调镜头、空间、靠近、聚焦，适合做市场展示和截图素材。

参考来源：

- Apple 2026 `(Not Boring) Camera`：大控件、触觉滚轮、复古相机质感、强手感。
- Apple 2026 `Caradise`：高沉浸细节、空间音频和材质真实感。
- Apple 2025 `Taobao`：3D / 空间对象的摆放、大小、控制和比较。
- Apple 2025 `Mela`：在特定工作模式下高亮当前步骤，其他信息自动降噪。

配色方案：

```text
Base:        #070604  near black
Warm Light:  #F7D08A  tungsten
Macro Green: #77E36B  optical green
Candidate:   #FFB84D  lens amber
Confirm:     #FF3B30  iOS red
Steel:       #A7B0B8  lens metal
Panel:       #17130E  warm dark panel
```

视觉设计：

- 主界面变成“微距取景器”：
  - 中心是大圆形光学镜片。
  - 外圈显示稳定度、变焦、光线。
  - 目标进入中心时，镜片边缘出现景深光晕。
- 候选区域不只是 bbox，而是被一个“放大镜预览泡”呈现：
  - 泡内显示 ROI 局部放大画面。
  - 泡外保留相机全局背景。
  - 用户直观看到“为什么要靠近这里”。
- 底部是相机式控制：
  - 左：手电。
  - 中：大号变焦拨轮。
  - 右：锁定 / 结束。
- Trophy 页面改成“样本胶片”：
  - 每次确认是一张胶片卡。
  - 展示 ROI、置信度、环境状态。

交互设计：

- 用户通过“靠近 + 对准 + 变焦”完成识别，App 像相机教练。
- 变焦不只是 Slider，而是触觉拨轮：
  - 1x、1.5x、2x、3x、5x 有刻度。
  - 到达推荐倍率时轻震。
- 候选太小时，系统显示“需要微距确认”，并出现 ROI 放大泡。
- 目标中心命中时，放大泡吸附进中心镜片，触发 Stage 2。
- 识别成功后冻结帧变成“证据照片”，可保存为训练样本。

动效设计：

- 扫描：镜片外圈慢速旋转，像对焦马达。
- 发现：ROI 放大泡从候选位置弹出，带轻微景深模糊。
- 对准：放大泡沿最短路径吸附中心，使用弹簧曲线。
- 放大：拨轮转动时，中心镜片有物理缩放反馈。
- 确认：快门式短黑场 80ms + 红色证据框 + 触觉成功。

优点：

- 记忆点最强，截图和宣传最容易出效果。
- 能把“靠近/放大”这个技术要求自然包装成微距体验。
- 与后续训练样本采集结合好，用户会理解“证据照片”的价值。

风险：

- 实现成本最高。
- 如果 ROI 预览处理不好，性能和延迟会受影响。
- 过度相机化可能让部分用户误以为这是拍照 App，而不是识别工具。

适合用户：

- 愿意探索、愿意多试几次的用户。
- 对视觉和动效敏感的用户。
- 适合 2.0 宣传图、App Store 截图和短视频展示。

实现建议：

- 第一期先做假实时 ROI 预览：复用当前帧裁剪生成 `UIImage`，限制刷新频率 5-8 FPS。
- 变焦拨轮独立成 `MacroZoomDial`，兼容普通 Slider 的无障碍替代。
- 中心镜片使用 SwiftUI shape + mask，不做 Metal，先控制复杂度。
- 真实 ROI 预览需要性能开关，老设备自动降级为普通候选框。

## 5. 2.0 模型方案

### 5.1 新管线

```text
Camera frame
  -> Quality Gate: light / blur / motion / background complexity
  -> Stage 1 Wide Search:
       low-threshold detector + classic dark-spot scanner ensemble
       output top-K candidate heat regions
  -> Temporal Aggregator:
       ByteTrack/SORT-like association, stable score, motion compensation
  -> Guidance Controller:
       tell user move closer / center / zoom / hold still
  -> Stage 2 Local Confirmation:
       high-resolution ROI crop
       detector/classifier ensemble
       calibrated threshold
  -> Result:
       confirmed / uncertain / dismissed
```

### 5.2 Stage 1：高召回搜索

目标：宁可多给 1-3 个候选，也不能漏掉远处蚊子。

具体任务：

- D-FINE 低阈值全帧搜索作为主候选源。
- Classic 暗点扫描作为辅助候选源，尤其针对白墙小黑点。
- 增加候选融合：
  - detector box
  - dark spot contrast
  - temporal stability
  - background smoothness
  - user motion stability
- 输出从“框列表”升级为“候选热区 + 优先级”。

验收指标：

- `Recall@Top3`：真实蚊子在前 3 个候选区域中的比例。
- `Candidate Stability`：同一候选在连续帧中的 ID 保持率。
- `False Candidate Rate`：每分钟误导用户靠近的候选数量。

### 5.3 Stage 2：高清确认

目标：用户靠近后明显提升真蚊确认准确率。

具体任务：

- 新增 `Stage2RoiRefiner`：
  - 接收候选 bbox。
  - 按 2x-4x 扩展 ROI。
  - 从原始相机帧裁剪，不从 416 缩放图裁剪。
  - 输出 224/320/416/640 多规格 ROI。
- 模型组合：
  - Classic CNN 做高速二分类。
  - D-FINE / YOLOX 对局部 ROI 复检。
  - 结果做 ensemble：分类器分数 + detector 分数 + 稳定度。
- 加入“不确定”状态：
  - 分数低但稳定：提示继续靠近。
  - 分数冲突：提示重新对准。
  - 分数高且稳定：确认。

验收指标：

- Stage 2 precision >= 95%。
- Stage 2 recall 不低于当前线上模型的有效召回。
- 真机单次确认延迟 < 300ms；最好 < 150ms。

### 5.4 跟踪和引导

当前 `ObjectTracker` 可以继续保留，但要升级思想：

- 不要只追高分框，也追低分但稳定的候选。
- 引入 ByteTrack 风格关联：高分候选确认轨迹，低分候选用于补轨。
- 增加相机移动补偿：通过 CoreMotion 和画面中心漂移估计候选位置。
- 目标状态从 `suspect / engaging / confirmed / dismissed` 扩展为：

```swift
case weakSignal
case stableCandidate
case guideToCenter
case readyToConfirm
case confirming
case confirmed
case uncertain
case dismissed
```

## 6. 数据和训练计划

### 6.1 数据优先级

1. **手机实测失败样本**
   - 用户说“不是蚊子”的 hard negative。
   - 用户说“明明有蚊子但没识别”的 missed positive。
   - 家庭墙面、天花板、暗角、污点、灰尘、纹理。

2. **Kaggle low-light bbox 数据**
   - 继续作为 detector 基础训练集。
   - 加强尺度分布分析，特别关注小框。

3. **Hugging Face bbox 数据**
   - 暂不直接等权混入。
   - 先可视化标注、尺度、box 风格、背景分布。
   - 通过过滤后再低权重混入。

4. **Mosquito Alert Tigapics**
   - 当前只有图像级标签。
   - 用于真实分布分析、分类预训练、主动学习候选池。
   - 不能用整图伪框训练 detector。

### 6.2 标注策略

建立 2.0 标注闭环：

- App 内本地保存 hard negative / missed positive。
- 导出为 Review Bundle：
  - 原图帧
  - 候选框
  - 模型分数
  - 用户动作：dismiss / confirmed / missed
  - 光线、变焦、运动状态
- 人工标注第一批：
  - 500 张 false positive hard negatives。
  - 500 张真实蚊子小目标 bbox。
  - 200 张复杂背景无蚊图。
- 用 Roboflow / CVAT / Label Studio 管理 bbox，不再手写零散 JSON。

### 6.3 训练实验矩阵

#### 实验 A：YOLOX Stage 1 高召回版

- 输入尺寸：416、640 对比。
- 数据：Kaggle + 人工 hard negatives + 过滤后的 HF。
- 目标：Recall@Top3 最大化。
- 输出：Stage1 detector，不直接作为确认模型。

#### 实验 B：D-FINE Stage 1/2 双用途版

- D-FINE 保留为主 detector 候选。
- 重点解决本地 MPS 训练问题；如果仍不稳定，使用 CPU smoke + 云端/外部 GPU 完整训练。
- 目标：定位更准，减少候选框偏移。

#### 实验 C：ROI Classifier 2.0

- Backbone：MobileNetV3-Small / MobileViT / 当前 CNN 对比。
- 输入：224、320、384 ROI。
- 数据：真实蚊子 ROI + hard negatives。
- 目标：Stage 2 precision >= 95%，真机延迟低。

#### 实验 D：SAHI-style 局部复检

- App 端不全帧切片，只对候选附近切片。
- 训练端做 slicing aided fine-tuning，增强小目标。
- 目标：远处小蚊子靠近后确认率提升。

#### 实验 E：RF-DETR nano 研究分支

- 不直接进线上。
- 目标：评估是否比 D-FINE/YOLOX nano 有更好的准确率/延迟比。

## 8. 验收指标

### 8.1 产品指标

- 首次用户完成一次扫描的比例 >= 80%。
- 用户能理解下一步动作的主观评分 >= 4/5。
- 设置页普通用户可见选项减少到 6 个以内。
- 真实使用中“误导性红框”明显减少。

### 8.2 模型指标

- Stage 1：
  - Recall@Top3 >= 90%。
  - 每分钟有效候选 <= 10。
  - Stage 1 平均延迟 <= 80ms。

- Stage 2：
  - Precision >= 95%。
  - Recall 较当前线上版本提升或不下降。
  - 单次确认延迟 <= 300ms。

- 端侧性能：
  - 识别时 UI FPS 不低于 30。
  - 连续使用 5 分钟无明显卡顿。
  - 设备不过热或降频后仍可用。

## 9. 优先级

P0：

- 真实 Stage 2 ROI 复检。
- 用户引导状态机。
- 失败样本采集和导出。
- 设置页普通/高级分层。

- 候选融合和方向引导。

P2：

- RF-DETR nano 研究。

- Trophy 复盘和成就系统。

## 10. 风险

- 如果继续只用公开数据，模型在真实家庭场景提升有限。
- 如果没有 hard negative，误报会长期存在。
- 如果 Stage 2 不做高清 ROI，只调阈值会牺牲召回。
- 如果设置页继续暴露过多模型参数，普通用户会降低使用意愿。
- 如果 App 内保存图像样本，需要严格保持本地、显式用户操作、清楚隐私说明。

## 12. 下一步建议
