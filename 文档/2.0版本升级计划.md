# Mosquito Finder 2.0 版本升级计划

更新时间：2026-06-27

## 1. 目标

2.0 版本围绕两个方向升级：

1. **界面和交互**：从“战术 HUD 工具”升级为“引导式猎蚊体验”。用户打开 App 后，不需要理解模型和参数，只需要跟随扫描、靠近、放大、确认的提示完成一次有效搜索。
2. **模型识别准确率**：从当前“全帧检测分数直接确认”升级为真正的两阶段视觉管线：Stage 1 大范围高召回搜索可疑区域，Stage 2 在用户靠近/放大后对局部高清 ROI 做高精度确认。

核心产品指标：

- 首次使用用户能在 15 秒内理解如何开始扫描。
- 大范围扫描时能稳定标出“可能有蚊子”的方向和区域，而不是只给零散框。
- 用户靠近候选区域后，App 能给出清晰的“继续靠近 / 放大 / 对准 / 已确认”反馈。
- 真实家庭场景下误报明显下降，且漏掉远处小目标的概率下降。

## 2. 当前代码现状

### 2.1 交互和界面

当前主界面集中在 `HuntingView`、`TargetOverlayView`、`RadarPulseView`、`TargetEffectsScene`：

- 已有深色相机全屏、绿色扫描线、准星、黄色/红色目标框、冻结帧和底部确认面板。
- 已有首次任务引导 `MissionGuideOverlay`，但引导和实时识别状态没有形成强闭环。
- 启动页视觉有“雷达 / 夜视仪”风格，但仍偏功能说明，缺少高级产品的层次、节奏和情绪设计。
- 设置页 `SettingsView` 已支持 D-FINE、YOLOX、Classic 三种模型和两阶段参数，但整体更像工程调参面板，不适合普通用户。
- Trophy 页面有统计数据，但还没有形成复用价值：用户看不出“这次为什么成功 / 下次怎么更快找到”。

### 2.2 模型管线

当前视觉入口在 `TargetCoordinator.processFrame()`：

- Stage 1：
  - Classic 模式：暗点扫描 + 局部对比度 + 背景平整度。
  - Detector 模式：D-FINE / YOLOX 全帧 416 输入检测，低阈值产生候选框。
- Tracker：
  - 当前 `ObjectTracker` 追踪稳定目标，`stableFrameCount` 控制稳定帧数。
- Stage 2：
  - Classic 模式：对 ROI 调用 `MosquitoClassifier.mlmodel`。
  - Detector 模式：目前不是高清 ROI 复检，而是直接用 Stage 1 detector 的 tracking confidence 通过高阈值确认。

这意味着当前 D-FINE / YOLOX 模式虽然在产品文案上是两阶段，但技术上更接近“全帧检测 + 稳定分数门控”。2.0 需要把它改成真正的：

```text
Stage 1: wide search / high recall / low confidence threshold
Stage 1.5: tracking + visual guidance + user movement/zoom coaching
Stage 2: high-resolution local confirmation / high precision
```

### 2.3 训练和数据现状

已有数据和结论：

- Kaggle low-light mosquito：约 7,487 个有效 bbox 样本，是当前最可用的真实检测数据。
- Hugging Face mosquito species detection：已有 bbox，但混入 YOLOX 后验证集表现下降，需要先做分布和标注质量分析。
- Mosquito Alert Tigapics：约 40,842 张可用图，但只有图像级物种标签，没有 bbox。不能直接当检测框训练集。
- 当前 YOLOX 最佳 F1：约 73.65%，高精度点接近 94.95% precision 但 recall 只有 12.62%。
- Mosquito Alert 伪标注等权混入曾造成退化，说明伪标签必须人工审核、分层采样、低权重使用。

## 3. 外部调研结论

### 3.1 小目标检测方向

蚊子在手机画面里通常是极小目标，远距离时可能只有十几个像素。小目标检测的主要难点是分辨率不足、背景纹理干扰、类别不平衡、标注噪声和真实场景域偏移。

可采用的方向：

- **切片/局部高分辨率检测**：SAHI 通过把高分辨率图像切成重叠 patch 来提升小目标检测效果。论文报告在多个检测器上能显著提升小目标 AP，适合我们做 Stage 2 高清局部确认。
- **多尺度特征和高输入分辨率**：Stage 1 不宜只把全帧压到 416；可保留低分辨率全帧搜索，同时对可疑区域做 640/768/1024 局部复检。
- **低分检测框也要追踪**：ByteTrack 的思想是不要过早丢弃低分框，而是通过时序关联判断是否是真目标。适合大范围搜索阶段提高召回。
- **硬负样本挖掘**：家庭墙面上的污点、螺丝、阴影、纹理、灰尘是主要误报来源。模型提升必须依赖真实手机失败样本，而不是继续堆公开数据。

### 3.2 模型候选

现有模型：

- D-FINE：定位精度强，适合主 detector，但当前本地训练和 CoreML 导出链路需要继续稳定。
- YOLOX：已有训练、导出和评估链路，适合作为可控 baseline。
- Classic CNN：作为 Stage 2 ROI fallback 价值仍高，尤其适合“放大后确认”。

建议新增评估：

- RF-DETR nano：2025 之后的轻量 DETR 路线，论文声称在实时 detector 上有更好的精度/延迟 Pareto，可作为 2.0 研究分支，不直接替换线上。
- MobileNetV3 / MobileViT 分类器：适合做 Stage 2 ROI 分类器，尤其是对高清裁剪图做蚊子 / 非蚊子二分类。
- SAHI 风格切片推理：不一定直接引入 Python SAHI 到 App，而是在 iOS 内实现轻量的“候选区域扩展 + 高分辨率裁剪 + 局部模型确认”。

### 3.3 iOS 端实现原则

- Core ML 仍应使用 `MLModelConfiguration.computeUnits = .all`，优先让系统调度 CPU/GPU/ANE。
- 避免每帧跑重模型；应使用帧率节流、运动稳定判断、候选追踪和局部触发。
- Camera、torch、focus、zoom 不只是功能按钮，而应成为引导闭环的一部分：环境太暗、画面抖动、候选太小、未对准时都给用户明确指令。

## 4. 2.0 产品设计方案

### 4.1 设计方向

视觉关键词：

- 深黑相机底、低饱和科技绿、冷白文字、少量红色警报。
- 少用“游戏化按钮堆叠”，多用专业仪器式反馈。
- 当前绿色战术 HUD 可以保留，但要降低噪声，让用户注意力集中在候选目标和下一步动作。

交互关键词：

- **引导式搜索**：告诉用户现在应该“慢扫墙面”“停稳”“靠近黄色区域”“放大到 2x”“保持中心”。
- **渐进确认**：不要突然红框；先显示候选强度、稳定度、距离中心、放大要求，再进入确认。
- **失败可解释**：没找到时告诉用户可能原因：太暗、太晃、背景太乱、离得太远。

### 4.2 主流程重构

#### Step A：启动前准备

替换当前静态功能说明为“30 秒猎蚊任务卡”：

- 第 1 步：打开手电，扫浅色墙面。
- 第 2 步：看到黄色提示，慢慢靠近。
- 第 3 步：目标进中心后放大确认。

实现：

- `MissionGuideOverlay` 改为可复用的 `GuidedMissionSheet`。
- 支持“今天不再显示”，但设置页可重新打开。
- 引导不使用长文字，改用 3 张短动效卡片。

#### Step B：搜索模式

当前 UI 是“扫描中 + 多个黄色框”。2.0 改成：

- 大范围候选用“方向引导”和“热区提示”，不要一开始就画太多框。
- 候选按稳定度聚合成 1-3 个优先目标。
- 顶部状态显示当前环境质量：
  - 光线：OK / 太暗
  - 稳定：OK / 太晃
  - 背景：OK / 纹理复杂
  - 目标：未发现 / 有候选

新增状态：

```swift
enum GuidanceState {
    case scanning
    case holdStill
    case moveCloser
    case centerCandidate
    case zoomIn(required: CGFloat)
    case confirming
    case confirmed
    case noSignal(reason: NoSignalReason)
}
```

#### Step C：候选引导

当 Stage 1 发现候选：

- 屏幕边缘显示方向箭头，提示用户移动相机。
- 候选进入中心区域后，显示“保持中心 / 放大到 2x”。
- 如果目标太小，不直接判定失败，而是提示靠近。
- 如果目标稳定超过 N 帧，再触发 Stage 2。

#### Step D：确认模式

Stage 2 不再只是高阈值分数门控：

- 用户靠近后，取候选周围扩大 ROI。
- 从当前高分辨率相机帧裁剪局部区域。
- 对 ROI 运行更高输入尺寸或分类器。
- 若仍不确定，提示“再靠近一点 / 再对准 1 秒”，而不是直接清除。

#### Step E：成功和复盘

确认后：

- 保留冻结帧红框。
- 增加“保存为训练样本 / 不是蚊子”两个小操作，但默认隐藏在二级菜单，避免打扰普通用户。
- Trophy 页面增加本次复盘：
  - 找到用时
  - 模型置信度
  - 用户是否靠近/放大
  - 是否生成可训练样本

### 4.3 设置页重构

普通用户设置页只保留：

- 检测模式：智能推荐 / 更敏感 / 更严格。
- 手电筒：自动 / 手动。
- 触觉反馈。
- 语言。
- 重新查看使用指南。

高级设置折叠到 Developer Lab：

- D-FINE / YOLOX / Classic 模型选择。
- Stage 1 / Stage 2 参数。
- 阈值、NMS、稳定帧、冷却时间。
- 诊断信息导出。

这样既保留工程能力，又不会让普通用户被模型概念劝退。

## 5. 2.0 模型方案

### 5.1 新管线

```text
Camera frame
  -> Quality Gate: light / blur / motion / background complexity
  -> Stage 1 Wide Search:
       low-threshold detector + classic dark-spot scanner ensemble
       output top-K candidate heat regions
  -> Temporal Aggregator:
       ByteTrack/SORT-like association, stable score, motion compensation
  -> Guidance Controller:
       tell user move closer / center / zoom / hold still
  -> Stage 2 Local Confirmation:
       high-resolution ROI crop
       detector/classifier ensemble
       calibrated threshold
  -> Result:
       confirmed / uncertain / dismissed
```

### 5.2 Stage 1：高召回搜索

目标：宁可多给 1-3 个候选，也不能漏掉远处蚊子。

具体任务：

- D-FINE 低阈值全帧搜索作为主候选源。
- Classic 暗点扫描作为辅助候选源，尤其针对白墙小黑点。
- 增加候选融合：
  - detector box
  - dark spot contrast
  - temporal stability
  - background smoothness
  - user motion stability
- 输出从“框列表”升级为“候选热区 + 优先级”。

验收指标：

- `Recall@Top3`：真实蚊子在前 3 个候选区域中的比例。
- `Candidate Stability`：同一候选在连续帧中的 ID 保持率。
- `False Candidate Rate`：每分钟误导用户靠近的候选数量。

### 5.3 Stage 2：高清确认

目标：用户靠近后明显提升真蚊确认准确率。

具体任务：

- 新增 `Stage2RoiRefiner`：
  - 接收候选 bbox。
  - 按 2x-4x 扩展 ROI。
  - 从原始相机帧裁剪，不从 416 缩放图裁剪。
  - 输出 224/320/416/640 多规格 ROI。
- 模型组合：
  - Classic CNN 做高速二分类。
  - D-FINE / YOLOX 对局部 ROI 复检。
  - 结果做 ensemble：分类器分数 + detector 分数 + 稳定度。
- 加入“不确定”状态：
  - 分数低但稳定：提示继续靠近。
  - 分数冲突：提示重新对准。
  - 分数高且稳定：确认。

验收指标：

- Stage 2 precision >= 95%。
- Stage 2 recall 不低于当前线上模型的有效召回。
- 真机单次确认延迟 < 300ms；最好 < 150ms。

### 5.4 跟踪和引导

当前 `ObjectTracker` 可以继续保留，但要升级思想：

- 不要只追高分框，也追低分但稳定的候选。
- 引入 ByteTrack 风格关联：高分候选确认轨迹，低分候选用于补轨。
- 增加相机移动补偿：通过 CoreMotion 和画面中心漂移估计候选位置。
- 目标状态从 `suspect / engaging / confirmed / dismissed` 扩展为：

```swift
case weakSignal
case stableCandidate
case guideToCenter
case readyToConfirm
case confirming
case confirmed
case uncertain
case dismissed
```

## 6. 数据和训练计划

### 6.1 数据优先级

1. **手机实测失败样本**
   - 用户说“不是蚊子”的 hard negative。
   - 用户说“明明有蚊子但没识别”的 missed positive。
   - 家庭墙面、天花板、暗角、污点、灰尘、纹理。

2. **Kaggle low-light bbox 数据**
   - 继续作为 detector 基础训练集。
   - 加强尺度分布分析，特别关注小框。

3. **Hugging Face bbox 数据**
   - 暂不直接等权混入。
   - 先可视化标注、尺度、box 风格、背景分布。
   - 通过过滤后再低权重混入。

4. **Mosquito Alert Tigapics**
   - 当前只有图像级标签。
   - 用于真实分布分析、分类预训练、主动学习候选池。
   - 不能用整图伪框训练 detector。

### 6.2 标注策略

建立 2.0 标注闭环：

- App 内本地保存 hard negative / missed positive。
- 导出为 Review Bundle：
  - 原图帧
  - 候选框
  - 模型分数
  - 用户动作：dismiss / confirmed / missed
  - 光线、变焦、运动状态
- 人工标注第一批：
  - 500 张 false positive hard negatives。
  - 500 张真实蚊子小目标 bbox。
  - 200 张复杂背景无蚊图。
- 用 Roboflow / CVAT / Label Studio 管理 bbox，不再手写零散 JSON。

### 6.3 训练实验矩阵

#### 实验 A：YOLOX Stage 1 高召回版

- 输入尺寸：416、640 对比。
- 数据：Kaggle + 人工 hard negatives + 过滤后的 HF。
- 目标：Recall@Top3 最大化。
- 输出：Stage1 detector，不直接作为确认模型。

#### 实验 B：D-FINE Stage 1/2 双用途版

- D-FINE 保留为主 detector 候选。
- 重点解决本地 MPS 训练问题；如果仍不稳定，使用 CPU smoke + 云端/外部 GPU 完整训练。
- 目标：定位更准，减少候选框偏移。

#### 实验 C：ROI Classifier 2.0

- Backbone：MobileNetV3-Small / MobileViT / 当前 CNN 对比。
- 输入：224、320、384 ROI。
- 数据：真实蚊子 ROI + hard negatives。
- 目标：Stage 2 precision >= 95%，真机延迟低。

#### 实验 D：SAHI-style 局部复检

- App 端不全帧切片，只对候选附近切片。
- 训练端做 slicing aided fine-tuning，增强小目标。
- 目标：远处小蚊子靠近后确认率提升。

#### 实验 E：RF-DETR nano 研究分支

- 不直接进线上。
- 目标：评估是否比 D-FINE/YOLOX nano 有更好的准确率/延迟比。

## 8. 验收指标

### 8.1 产品指标

- 首次用户完成一次扫描的比例 >= 80%。
- 用户能理解下一步动作的主观评分 >= 4/5。
- 设置页普通用户可见选项减少到 6 个以内。
- 真实使用中“误导性红框”明显减少。

### 8.2 模型指标

- Stage 1：
  - Recall@Top3 >= 90%。
  - 每分钟有效候选 <= 10。
  - Stage 1 平均延迟 <= 80ms。

- Stage 2：
  - Precision >= 95%。
  - Recall 较当前线上版本提升或不下降。
  - 单次确认延迟 <= 300ms。

- 端侧性能：
  - 识别时 UI FPS 不低于 30。
  - 连续使用 5 分钟无明显卡顿。
  - 设备不过热或降频后仍可用。

## 9. 优先级

P0：

- 真实 Stage 2 ROI 复检。
- 用户引导状态机。
- 失败样本采集和导出。
- 设置页普通/高级分层。

P1：

- 候选融合和方向引导。
- ROI classifier 2.0。
- hard negative 数据闭环。
- 真机性能面板。

P2：

- RF-DETR nano 研究。
- SAHI-style 训练端切片增强。
- Trophy 复盘和成就系统。

## 10. 风险

- 如果继续只用公开数据，模型在真实家庭场景提升有限。
- 如果没有 hard negative，误报会长期存在。
- 如果 Stage 2 不做高清 ROI，只调阈值会牺牲召回。
- 如果设置页继续暴露过多模型参数，普通用户会降低使用意愿。
- 如果 App 内保存图像样本，需要严格保持本地、显式用户操作、清楚隐私说明。

## 12. 下一步建议

建议先做 P0，不要先重训大模型：

1. 实现引导状态机和新的主 HUD，让用户行为数据可采集。
2. 实现 Stage 2 ROI 高清复检，验证真正两阶段链路是否有效。
3. 开启本地 hard-negative/missed-positive 采集。
4. 用第一批真实失败样本重训 ROI classifier 和 Stage 1 detector。

这样能最快形成“用户体验改进 -> 真实数据增加 -> 模型继续变准”的闭环。
